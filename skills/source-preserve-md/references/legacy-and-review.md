# 구형 문서와 원본 대조·교정

## 실제 로컬 변환

- HWP5: `pyhwp==0.1b15`, `olefile`, `lxml`, `six`를 사용한다. 실제 CFB 스트림과 FileHeader로 판별한다. 압축 해제·출력 크기를 제한하고 암호/배포용 문서는 자동 해제하지 않는다.
- pyhwp XHTML에서 빠지는 각주/미주는 모델 XML에서 본문 참조·내용·왕복 링크를 보완한다. 연결 문단이 모호하면 추정하지 않고 알린다. 모델 Text/표 수와 변환 내용을 대조해 누락을 경고하고 CLI 종료 2로 구분한다.
- HWP의 PrvText 원래 바이트와 UTF-8 미리보기, 모델 XML, 스타일/이미지를 묶음에 보존한다. 내장 미리보기의 <> 같은 개체 표식과 화면의 원문 글자는 구분한다. 스타일을 유지한 파생 HTML은 같은 폴더에서 상대 자산을 찾도록 연결한다.
- DOC/XLS/PPT: 설치된 LibreOffice를 이용한다. `SOURCE_PRESERVE_SOFFICE`로 실행 파일을 지정할 수 있다. 현재 컴퓨터는 Codex의 번들 실행기를 확인했다. 새 임시 프로필에 매크로·활성 콘텐츠·Writer/Calc 링크 갱신 끄기 설정을 적용한다. 사용자 Office 프로필을 가져오지 않는다.
- 변환 OOXML과 원본을 함께 저장한다. 변환된 단위 위치는 `converted:FORMAT/...`이므로 이를 원래 바이너리의 정확한 페이지 좌표로 해석하지 않는다. 파서 손실·폰트/페이지 배치·고급 개체의 전체성을 인증하지 않는다.

## 대조·교정 사용

1. 프로그램의 결과에서 “원본 대조·OCR 교정”을 연다. 오프라인에서는 전체 ZIP을 풀고 `04_원본대조.html`을 연다. HTML 한 파일만 옮기면 참조 이미지가 빠진다.
2. 원본 이미지의 해당 위치와 현재 줄/셀·후보를 대조하고 필요한 항목만 고친다. 이 화면은 HWP 변환 참조본·수식 XML·원본 파일 링크도 제공한다.
3. “변경 항목의 교정 JSON 받기”로 저장한다. 프로그램 결과 화면에서 “교정 JSON 적용”을 눌러 같은 묶음에 연결한다.
4. CLI 사용 시:

```text
python3 scripts/run.py correct 기존_결과폴더 --corrections ocr-corrections.json --out 새_교정결과폴더
python3 scripts/run.py validate 새_교정결과폴더
```

`correct`는 OCR을 다시 실행하지 않는다. 기존 묶음과 원본을 수정하지 않고, 새 묶음에 교정 후 MD·구조·대조 화면·이력을 기록한다. source_sha256·대상·예상 원문이 다르면 중단한다. 셀·줄은 좌표별로 바꾸며 전체 문자열 일괄 치환을 하지 않는다. `--ocr-corrections`로 새 변환에 입력할 수도 있지만, 기존 결과를 대조한 교정은 `correct`가 재인식 변동을 피하는 경로다.

교정 이력은 `human_corrections`와 `manifest.derived_from`에서 읽는다. 사용자 제공 교정, 로컬 OCR 재인식, 독립 원본 대조는 별개이며 `partial`을 자동 verified로 올리지 않는다. 암호 문서 거부·시간 초과·자료별 미지원과 단순한 안내 경고를 구분한다.
