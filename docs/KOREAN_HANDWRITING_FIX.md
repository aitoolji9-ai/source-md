# 한글 손글씨 오인식 원인과 보완 — 0.9.3

0.9.2 대비 **기존 한글 평가 4페이지의 문자 오류 수가 360→353개, CER 28.08%→27.54%**로 줄었다. 별도 실제 필기 궤적 64줄도 두 묶음에서 각각 71→67개, 55→47개로 줄었다. 개선 폭은 제한적이며, 어려운 사진 전체가 해결된 것은 아니다.

## 이전에 한글 수치가 그대로였던 이유

1. 0.9.2의 영어 보완은 ASCII Latin 줄에만 적용했다. 한글에 그 후보 선택을 적용하지 않았다.
2. 기존 한글 줄 재인식은 원본·잘라낸 줄·배율을 바꾼 줄의 **전체 문자열** 일치를 요구했다. 개발 자료에서 올바르게 읽힌 중간 한글도 문장 끝의 다른 글자나 문장부호가 다르면 보류됐다. 후보를 생성하는 것과 실제 MD에 채택하는 것은 달랐다.
3. 작은 글씨를 멀리서 비스듬히 찍은 사진에는 최초 검출 누락과 글자 자체의 혼동도 남는다. 이번 보완은 이미 검출된 줄의 확인 가능한 후보만 바꾼다. 가장 어려운 기존 사진 `ko-07`은 여전히 190/383 오류로 같았다.
4. 원출처 전사에 없는 노트 표식·주석, 정규화된 철자와 읽기 순서 차이도 전체 페이지 CER에 포함된다. 원문을 지워 점수를 높이지 않았다.

개발 실험은 `ko-01,02`만 사용했다. 페이지의 사전 보정을 켜기만 한 후보도 시험했지만, 문맥만으로 필자의 철자를 고치는 위험 때문에 그대로 채택하지 않았다. 이전에 비교한 별도 한국어 OCR 모델도 이 자료에서 더 나빠 기본 의존성에 추가하지 않았다.

## 바꾼 동작

- 보류된 한글 줄이 있으면 같은 이미지의 페이지 문맥 인식을 한 번만 요청한다. 위치가 일치하는 단일 후보만 비교하며, 다른 원본 줄과 겹치거나 숫자열이 달라지거나 원문 뒤에 글자를 덧붙인 후보는 새 보완으로 채택하지 않는다.
- 페이지 문맥과 서로 다른 줄 인식 후보가 같은 결과를 뒷받침하면 전체 줄 후보를 채택할 수 있다. 사전 보정을 끈 후보가 반드시 포함된다.
- 전체 문장은 다르지만 한글 글자만 일치하는 경우, 같은 위치의 1~2글자 치환이 페이지와 줄 후보 둘에서 확인될 때만 그 부분을 바꾼다. 주변에서 같게 읽힌 글자 4개 이상을 요구한다. 이 부분 치환은 원래 띄어쓰기·숫자·문장부호를 그대로 둔다. 새로운 문장을 추측하거나 단어 사전을 끼워 넣지 않는다.
- 원본 인식, 모든 요청 응답, 원본 좌표, 페이지 후보, 선택한 글자와 근거를 `refinement.page_context`, `line_refinements[].page_context_candidate`, `span_selections`에 보관한다. 원본 이미지·원본 OCR 관측 목록을 덮어쓰지 않는다.
- 기존 256요청·180초 상한 안에서 실행한다. 페이지 요청 실패는 한 번 기록하고 원래 결과를 유지한다. 숫자·기하·모호한 후보·사전 보정만의 일치·요청 실패 경계를 시험했다. 후보 합의도 정확도 인증이 아니며 결과는 계속 원본 대조가 필요한 `partial`이다.

기본 프로그램·CLI·공통 스킬은 같은 엔진을 쓴다. 외부 생성형 AI/OCR API를 호출하지 않으며 추가 OCR 모델·런타임을 설치하지 않는다. macOS 필수 설치 검사는 유지했다.

## 같은 입력으로 다시 채점한 결과

CER은 NFC 후 공백만 제거한 Unicode 편집 거리/정답 문자 수다. 숫자·대소문자·문장부호를 유지하며 낮을수록 좋다. `100-CER`을 정확도라고 부르지 않는다.

| 자료 | 표본/정답 문자 수 | 0.9.2 오류 수/CER | 0.9.3 오류 수/CER |
|---|---:|---:|---:|
| 기존 한글 손글씨 개발 | 2페이지 / 755 | 57 / 7.55% | 54 / 7.15% |
| 기존 한글 손글씨 평가 | 4페이지 / 1,282 | 360 / 28.08% | 353 / 27.54% |
| 새 필기 궤적 A | 32줄 / 509 | 71 / 13.95% | 67 / 13.16% |
| 새 필기 궤적 B | 32줄 / 473 | 55 / 11.63% | 47 / 9.94% |
| 기존 인쇄 대조군 | 2개 / 904 | 19 / 2.10% | 18 / 1.99% |
| 기존 영문 개발 | 8줄 / 325 | 29 / 8.92% | 29 / 8.92% |
| 기존 영문 평가 | 8줄 / 299 | 47 / 15.72% | 47 / 15.72% |

사진 페이지와 필기 궤적은 별도로 집계한다. 모든 입력의 개별 점수·해시와 NFC/NFD 수치는 [결과 JSON](KOREAN_HANDWRITING_RESULTS.json)에 기록한다. 실행 실패나 미인식 사례를 점수에서 빼지 않는다. 영어 인식은 그대로이며 전체 손글씨를 해결했다고 해석하지 않는다.

## 새 평가 자료와 한계

- 기존 사진·IAM의 출처와 범위는 [0.9.2 보고서](HANDWRITING_BENCHMARK.md)를 따른다. 기존 4페이지는 이미 여러 번 평가에 사용했으므로 새 봉인 평가로 부르지 않는다.
- 추가 자료는 [Korean Handwriting Strokes](https://huggingface.co/datasets/jbaudanza/korean-handwriting-strokes)의 고정 판본 `a821f48585613e6c24016315c0dc1eb6498a4f6a`다. 실제 사람이 펜으로 쓴 궤적을 고정 선 두께로 이미지화했다. 손글씨 폰트나 생성된 필기 이미지가 아니며, 사진도 아니다. 원출처의 문장 내용은 한국어 Wikipedia 또는 생성 문장이지만 궤적은 실제 필기다.
- 64줄 모두 한 필자다. A의 32행은 첫 정책 전, B의 다른 32행은 글자 보완 정책을 고정한 뒤 선택·준비했다. A는 이후 회귀 검증에 재사용했고 B의 결과로 코드를 조정하지 않았다. 새 필자·다양한 촬영 조건에 대한 성능 인증이 아니다.
- 선택은 A `0,137,...,4247`, B `68,205,...,4315`의 고정 행이다. 전체 궤적 범위를 유지하고 펜을 뗀 구간을 연결하지 않는다. OCR 결과나 정답에 맞춰 궤적을 지우거나 정답·분모를 수정하지 않았다.
- 원출처 파일·개별 이미지·전사 SHA-256과 출처 표시는 [자료 목록](../examples/handwriting-inputs/korean-strokes.json)에 있다. 제3자 이미지·전체 전사·모델 가중치는 배포본에 포함하지 않는다.

## 재현

기본 설치 후 별도 연구 자료 준비에만 선택 패키지 `pyarrow`를 사용한다. 프로그램의 필수 의존성은 아니다.

```sh
sh install.sh --dev
uv run --frozen --with 'pyarrow==26.0.1' python scripts/prepare_korean_strokes.py --out outputs/korean-strokes
uv run --frozen python scripts/benchmark_handwriting.py run --data outputs/korean-strokes --out outputs/korean-current --engine program
```

준비기는 고정된 공개 Parquet를 내려받아 SHA-256을 확인하고 64개 이미지를 만든다. 이미 파일이 있으면 `--source /absolute/path/to/recordings.parquet`로 재사용할 수 있다. 이전 버전을 별도 설치한 뒤 같은 실행기에 `--program-python /absolute/path/to/old/.venv/bin/python`을 지정하면 같은 입력을 전후 비교할 수 있다. 기존 24입력의 준비 방법은 이전 보고서의 `benchmark_handwriting.py prepare`를 사용한다. 전체 전사가 담긴 `outputs`는 공개 Git에 추가하지 않는다.

## 배포 전 검증

88개 입력의 전후 176개 실제 변환 묶음을 다시 열어 원본 SHA-256·생성 버전·실제 OCR 텍스트·등록 자산 무결성을 확인했다. NFC/NFD 편집 거리를 DP와 Myers 두 알고리즘으로 계산한 값 704개가 일치했다. 입력별 개선 15개·동일 73개·악화 0개였다. 회귀 테스트 130개와 설치 배포본 검사 20개가 통과했고, 기존 표 4개의 56개 셀은 값·행열·병합·빈칸이 일치했다. 비표 대조군 28개에서 거짓 표가 없었다. 이 검증은 시험한 입력과 환경의 결과이며 모든 한글 손글씨의 정확도 인증이 아니다.
