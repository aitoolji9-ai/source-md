# 대용량 PDF · 초기 OCR 우선 · 중단/재개/통합 — 0.9.4

0.9.3은 PDF 전체가 100대상·256요청·180초를 공유했다. 앞쪽 한글 줄과 셀에 요청을 반복하면 뒤쪽을 읽기 전에 예산을 소진했다. 작은 화면 무늬를 표로 잡고 높이8px 셀에 상하4px 여백을 적용해 오류가 나는 별도 결함도 있었다. 단순히5쪽·1쪽 PDF를 다시 만들어 호출하는 것으로 두 문제가 함께 해결되지 않았다.

0.9.4는 **모든 페이지의 초기 인식을 먼저 저장하고, 페이지 체크포인트에서 미처리만 재개하여 같은 책 MD에 통합**한다. 임시 PDF 조각이나 중복 원본 사본을 만들지 않는다. `source/`, `assets/`, 전체 페이지 위치와 원본 좌표를 보존하며 자동 추출의 `partial`은 유지한다.

## 사용

```sh
uv run --frozen preserve-md inventory 원본PDF폴더
uv run --frozen preserve-md convert 책.pdf --out outputs/책
uv run --frozen preserve-md status outputs/책
uv run --frozen preserve-md resume outputs/책
```

`inventory`는 지정 폴더 바로 아래의 PDF 목록·크기·SHA-256·쪽수를 OCR 없이 읽는다. 출력 폴더 아래의 원본 사본이나 예전 재시도 PDF를 재귀로 섞지 않는다.

`status`는 실제 쓰기 잠금, 저장 완료 쪽수, 남은 수와 실패 수를 작은 JSON으로 반환한다. 저장된 상태와 현재 실행 중인 쓰기를 구별한다. `resume`은 원본·페이지 체크포인트·완료 자산의 해시를 검증하고 저장되지 않았거나 실패한 부분만 수행한다. 같은 폴더를 동시에 쓰는 두 번째 실행은 거절한다.

실행 시간을 나누고 싶다면 다음처럼 페이지 작업 수를 제한한다. 기본모드에서는 한 쪽이 하나의 작업이며, 심화모드에서는 초기/심화 단계가 각각 작업이다.

```sh
uv run --frozen preserve-md convert 책.pdf --out outputs/책 --pdf-max-pages 20
uv run --frozen preserve-md resume outputs/책 --max-pages 20
```

- 종료0: 선택한 모드의 자동 처리가 끝남. OCR 정확도 인증이 아님.
- 종료3: 지정한 작업 수에서 안전하게 중간 저장함. 동일 폴더에 `resume` 실행.
- 종료2: 확인할 실패가 있음. 성공한 다른 쪽과 초기 OCR은 보존함. 원본/완료 자산이 바뀌었으면 재개를 중단함.

실제 프로세스가 종료되더라도 완료된 페이지는 재사용한다. 실행 중이던 미확정 페이지는 다시 시도할 수 있으며, 그 시도의 요청 수를 알 수 없으면 중단 시도로 별도 표시한다. 저장 완료 페이지가 재실행됐다는 뜻은 아니다. PDF 출력은 `00_원본복원.md` 하나에 원본 쪽번호 순으로 통합된다. 상대 이미지와 원본 링크를 유지하려면 전체 결과 폴더를 보관한다.

0.9.3의 옛 부분 결과에는 새 체크포인트가 없다. 원본으로 새 결과 폴더에 한 번 시작한다. 기존 결과를 덮어쓰지 않는다.

## 기본/심화 모드와 실패 처리

- `--ocr-detail text`가 PDF 기본값이다. 모든 대상 페이지를300dpi(최대변4096px)로 초기 인식한다. 표의 위치와 관측 글자가 안전하게 대응할 때만 표를 구성하고, 불확실한 도형·표는 원래 글자를 읽을 수 있게 보존한다.
- `--ocr-detail full`은 생성할 때 지정한다. 전체 초기 인식과 체크포인트를 저장한 다음 줄/셀 심화 인식을 한다. 심화 예산은 페이지 작업당 최대256요청·180초이며, 심화 실패가 초기 OCR을 지우지 않는다. 모든8권을 심화모드로 재처리한 시험은 하지 않았다.
- 일반 이미지 파일의 기존 손글씨·표 심화 인식은 유지한다. PDF 기본값의 변경과 구별한다.
- 고정 여백으로 소멸하는 작은 셀을 가진 표 후보는 배제하고 원래 관측 글자를 유지한다. 구조 분석이 실패해도 초기 글자·좌표를 보관하며 `ocr_layout_fallback`으로 표시한다.
- 네이티브 PDF 레이아웃 JSON에는 이미지 바이트의 문자열 표현을 반복 저장하지 않고 실제 이미지 자산을 참조한다. 원본 PDF와 이미지 파일 자체는 보존한다.

체크포인트의 작업 파일(`pdf-job.json`, `checkpoint/`)은 재개 시 별도로 검증한다. 문서 묶음의 일반 `validate`는 원본·등록 자산·MD 구간의 무결성 검사다. 두 검사의 범위를 혼동하지 않는다. CLI는 큰 관측 목록 대신 요약을 출력하며 전체 자료는 JSON 파일에 남긴다.

## 실제8권으로 처음부터 검증

제공된8권을 기존 추출 결과에서 가져오지 않고 원본으로 새 폴더에 변환했다. 개발 검증 후 새 폴더에서8권을 다시 전체 실행하고, 최종 코드에서 재개·결과 재조회와 회귀 검사를 마쳤다. 아래 수치는 최종 실행의 기록이며 [원본 해시·입력별 수치](PDF_BOOKS_VALIDATION.json)를 함께 제공한다. 유료/개인 자료의 PDF·이미지·전체 전사는 저장소나 배포본에 넣지 않는다.

| 입력 | PDF 쪽수 | 초기 OCR 대상/확정 요청 | 결과 |
|---|---:|---:|---|
|1|127|34|처리·통합 완료|
|2|221|83|처리·통합 완료|
|3|272|214|처리·통합 완료|
|4|172|163|처리·통합 완료|
|5|137|63|처리·통합 완료|
|6|110|88|처리·통합 완료|
|7|125|125|처리·통합 완료|
|8|224|137|처리·통합 완료|
|합계|1,388|907|8권 완료|

8권 각각2쪽에서 체크포인트 종료3을 확인한 뒤 재개했다. 첫 권은 실행 도중 실제 SIGTERM으로 종료시키고 다시 재개했다. 저장 완료 페이지의 중복 초기 OCR은0회였으며, 완료 후 재실행도 OCR이나 문서 바이트를 바꾸지 않았다. 원본 PDF 사본은 권당1개다.

결과를 다시 열어 다음을 확인했다.

- 원본 PDF8개 SHA-256, 모든1,388쪽의 텍스트층과 MD 원문 블록·페이지 순서 일치.
- 초기 OCR 관측32,910개가 네이티브 텍스트 또는 OCR MD에 남음. 관측 문자열이 MD에서 빠진 경우0개.
- PDF 텍스트층과 OCR 글자가 모두 없는 쪽0개. 이는 각 글자가 정확하다는 뜻이 아니다.
- 등록 자산과 MD 구간 무결성 통과. MD의 로컬 이미지/관측자료 링크도 실제 파일을 가리킴.
- 원래 실패한2권152쪽의 기본/심화 모드 모두 처리 완료. 기본은1회, 심화까지는 총137회이며 잘못된 크롭 예외가 없음.
- 실패한 쪽 뒤의 정상 쪽 진행, 실패 부분만 재시도, 구조 오류 뒤 초기 글자 보존, 원본/체크포인트 변조 거절, 동시 쓰기 거절, 상태 읽기 전용, PDF 링크 좌표 보존 등 회귀145개 통과.
- 설치 배포본의 실제 프로그램·스킬·PDF 체크포인트/재개·읽기 전용 상태 조회24검사 통과.
- 기존 손글씨24표본의 전후 오류 수 동일. 기존 표4개의56개 셀 값·행열·병합·빈칸도 일치.

OCR 정답 전사를 만들거나 모든 도표/이미지를 의미적으로 대조한 시험은 아니다. 이 보고서의 처리 완료·빈쪽0·관측 보존을 모든 단어의 정확도 또는 원본 시각 복제 인증으로 해석하지 않는다. GitHub CI는 생성한 시험 PDF와 공개 시험 자산으로 검사하며 이 비공개8권 자체를 실행하지 않는다.

## 같은 경로 재현

본인에게 사용 권한이 있는 로컬 PDF를 준비한다. 이 실행기는 원문을 외부로 전송하지 않는다. 결과 폴더는 존재하지 않는 새 폴더여야 한다.

```sh
sh install.sh --dev
uv run --frozen python scripts/verify_pdf_resume.py 첫번째.pdf 두번째.pdf --out outputs/pdf-resume-check
```

8쪽보다 긴 첫 입력에서는 실제 자식 프로세스를 SIGTERM으로 끊는 시험도 수행한다. 사용자나 다른 앱의 프로세스는 건드리지 않는다. 책별 초기 변환/중단/재개 로그와 `verification.json`을 남긴다. 전체 전사가 들어 있는 출력 폴더는 공개 Git에 추가하지 않는다.
