# 필수 환경을 통과해야 설치 — 0.9.0

0.9.0부터 기본 로컬 OCR을 필수 기능으로 취급한다. macOS·64비트 CPU·Swift 개발 도구·Python 3.12 이상·한국어/영어 Vision OCR·설치 공간 검사를 통과해야 설치한다. 0.8.0의 Linux 설치/CI 성공 기록은 이전 정책의 결과이며 현재 설치 허용을 뜻하지 않는다.

## 설치 전 검사

`sh install.sh`는 운영체제와 도구를 먼저 검사한다. Linux·Windows이거나 Swift/uv가 없으면 프로젝트 가상환경이나 의존성 설치 전에 종료한다. uv는 필요한 Python 3.12를 준비하고, 의존성이 없는 `preflight.py`로 남은 필수 환경을 확인한다. Python 준비는 프로그램 패키지 설치와 구분한다.

- 설치 위치의 여유 공간 **1GiB 이상**은 설치 캐시·Python·환경·임시파일을 위한 정책이다. 이전 빈 캐시 설치에서 해당 구성 합계가 약 615MiB였으며, 문서 변환 결과 저장 공간은 별도로 필요하다. RAM 용량이나 macOS 버전 번호를 근거 없이 최소 사양으로 선언하지 않는다.
- 포함한 고정 시험 이미지의 **영어·숫자·한국어를 실제로 읽어** 비교한다. 실제 추출에 쓰는 동일한 Swift OCR 소스를 컴파일하고 실행한다. 단순히 `swiftc` 파일이 있다는 이유로 통과시키지 않는다.
- 실패 항목과 해결 방법을 출력하고 종료 코드 **2**로 중단한다. 건너뛰기/강제 설치 옵션은 제공하지 않는다.
- `sh install.sh --check-only`는 환경 검사만 수행한다. `sh install.sh --dev`도 같은 필수 검사를 거친 뒤 개발 의존성을 설치한다.

## 우회 경로 방지와 배포 경계

소스의 PEP 517/660 빌드 백엔드도 같은 검사를 호출한다. 따라서 `uv sync`, 소스에 대한 `pip install`, editable 설치를 직접 요청해도 필수 검사를 수행한다. 일반 프런트엔드가 만든 빈 가상환경/격리 빌드 도구 폴더와 프로그램 패키지 설치 성공은 구분한다.

미리 빌드된 wheel은 설치 시 임의 사전 검사 코드를 실행하는 형식이 아니다. 그래서 **0.9.0 공식 릴리스는 검사기를 포함한 소스 ZIP·소스 배포본만 제공**하고, wheel은 개발/검증 과정에서 로컬로만 만든다. 내부 검증 wheel도 macOS 플랫폼 태그를 사용해 Linux/Windows에서 호환 패키지로 선택되지 않게 한다. 근거: [Python 패키징 설치 흐름](https://packaging.python.org/en/latest/flow/).

설치 후에도 `convert`, `serve`, 교정·스킬 설치 경로는 필수 환경을 다시 확인한다. 설치 뒤 Swift나 OCR 실행 환경이 사라진 경우 부족한 항목을 표시하고 실행을 중단한다. `doctor`는 도구 존재 진단이고, `preflight`는 실제 OCR을 포함한 승인 검사다.

브라우저와 LibreOffice는 추가 기능의 의존성이다. 기본 설치의 필수 조건과 구분하며, 해당 도구가 없으면 동적 수집/구형 Office 실행을 오류로 보고한다. 원본을 보관한 부분 결과를 전체 성공으로 승격하지 않는다.

## 검증

표준 라이브러리만 사용하는 `tests/test_preflight_bootstrap.py`는 OS·Python·CPU·Swift·공간 부족·OCR 실패/시간 초과·빌드 백엔드 거부를 확인한다. 실제 macOS OCR/설치 성공과 Linux/Windows의 설치 거부는 CI에서 각각 확인한다. 모의 조건 시험과 실제 OS 실행 결과는 별도로 집계한다.

이 검사는 설치 가능 환경과 OCR 작동 여부를 확인한다. 일반 문서 전체의 인식/의미/시각 정확도를 인증하는 것은 아니다. 이전 공개 검증은 [0.8.0 기록](PUBLISHED_VERIFICATION.md)으로 보존한다.
